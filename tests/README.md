# Тесты

Здесь лежат модульные тесты для игры. Писали их по плану тестирования из SRS (раздел 7), поэтому у каждой группы тестов в названии стоит номер пункта из плана, например «4.1 Инверсия клеток». Так проще сверять, что из плана уже покрыто.

Тесты запускаются прямо в браузере. Node.js и npm ставить не нужно.

## Как запустить

Если просто открыть `tests/index.html` двойным кликом, ничего не заработает: браузер не грузит ES-модули с `file://`. Поэтому сначала поднимаем локальный сервер из корня проекта:

```bash
python -m http.server 8000
```

и открываем http://localhost:8000/tests/

Сверху будет итог («Пройдено: 70, провалено: 0»), ниже — список всех тестов. Зелёные прошли, красные упали, и рядом с упавшим написано, что ожидалось и что получилось.

## Что где лежит

```text
tests/
├── index.html          # страница, которая запускает все тесты
├── unit/               # сами тесты, по одному файлу на класс
│   ├── Game.test.js
│   ├── HUD.test.js
│   ├── BoardInput.test.js
│   └── BoardRenderer.test.js
└── lib/                # вспомогательный код
    ├── test-runner.js  # describe / it / expect
    └── helpers.js      # пустое поле, подсчёт минимального решения и т.п.
```

**Game.test.js** — основная часть. Проверяет, что клик переворачивает правильные клетки (центр, угол, край), что счётчик ходов считает и сбрасывается, что победа засчитывается только при полностью погашенном поле и что после 15-го уровня игра заканчивается. Отдельно проверяется генерация: каждый уровень генерируется по 50 раз, и для каждого поля считается самое короткое решение. Оно должно совпадать с номером уровня. Ещё есть тесты на `subscribe` / `notify`.

**HUD.test.js** — счётчик, сообщение о победе и кнопка перезапуска. Заодно проверяется, что HUD не падает, если какого-то элемента нет на странице.

**BoardInput.test.js** — перевод координат клика в клетку. Сюда входят клик в зазор между клетками, клик мимо поля, растянутый canvas, быстрые клики подряд и то, что после конца игры клики не работают.

**BoardRenderer.test.js** — какие клетки рисуются включёнными, подсвеченными и нажатыми. Сам цвет здесь не проверяется, только логика.

## Почему без Jest

Игра у нас полностью клиентская и работает без сборки, поэтому тесты тоже сделали без внешних зависимостей. `lib/test-runner.js` — это маленький самописный аналог `describe` / `it` / `expect`, его хватает для наших проверок.

## Что проверяем руками

Часть пунктов из плана автоматически не проверить, их проходим вручную:

- свечение включённых клеток и эффекты наведения/нажатия на клетках и кнопке (4.5);
- перезагрузка страницы через F5 (4.6) — в тестах проверяется только то, что новая игра начинается с уровня 1 и нулевого счётчика;
- сообщение «Для игры необходимо включить JavaScript», когда JS отключён (4.7).
